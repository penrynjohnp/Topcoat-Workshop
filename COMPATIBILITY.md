Lab 12 provisions **two** user-assigned managed identities: `infra/modules/identity.bicep` is a single reusable factory module that `main.bicep` instantiates twice — once for the app (ACR pull, Key Vault Secrets User, PostgreSQL Entra administrator) and once for a narrowly-scoped bootstrap identity (Key Vault Secrets Officer only, never attached to the container app, never granted ACR pull or database access). The cookie signing key secret is created by `infra/modules/secret-bootstrap.bicep`, an idempotent `Microsoft.Resources/deploymentScripts` (`kind: 'AzureCLI'`) resource running under the bootstrap identity; `main.bicep`'s `app` module declares `dependsOn: [secretBootstrap]` because Azure Container Apps validates `keyVaultUrl` secret references at deploy time and fails the whole deployment if the target secret doesn't exist yet — a postprovision hook, which only runs after the app module is already submitted, is too late to create it. Consequently `scripts/azd-postprovision.sh` never creates or reads a secret value; it is read-only control-plane verification that the deployed container app is attached to its own user-assigned identity and that its Key Vault secret reference resolves through that same identity. Lab 12's `postgres.bicep` registers the *app's* identity (not the bootstrap identity) as the PostgreSQL Entra *administrator* — a bootstrap shortcut that keeps the lab to one extra Bicep module rather than a third identity, not a least-privilege pattern for production, where the administrator role belongs to a human or break-glass identity and the app gets a narrower Entra role. Azure Files was deliberately not used to keep SQLite in Lab 12: Container Apps' Azure Files integration authenticates the mount with a storage account key, not a managed identity, which would have reintroduced exactly the stored-secret pattern the "managed identity everywhere" rule forbids — PostgreSQL with Entra-only auth (`activeDirectoryAuth: 'Enabled'`, `passwordAuth: 'Disabled'`) replaces it instead. |topcoat-icon cache write is not atomic; CI stages one crate first

## Upgrading

1. Bump versions in the workspace `Cargo.toml` (`[workspace.dependencies]`) and `scripts/setup.sh`.
2. `cargo build --workspace && cargo test --workspace`.
3. Fix breakages lab by lab; each fix PR adds a row here.

## 0.8.0 upgrade notes

- Upstream v0.8.0 adds runtime signal persistence, signal parameters for shards, signal tracking during page/shard reruns, and morph-based HTML updates; these changes do not affect Labs 01-06 because they do not use signals.
- Upstream v0.8.0 also adds `TowerRoute::any` and treats empty form/query values as `None` for `Option<T>`; neither behavior is exercised by Labs 01-06.
- Labs 01-06 all pass `scripts/check-lab.sh` without source or manifest changes. No compile or test breakage was observed in this range.
- Lab 09 broke in three places on 0.8.0. The `signal name = value;` form inside `view!` is gone, so `_marketing.rs`, `_marketing/berths.rs`, and `_marketing/vessels.rs` each failed with `error: expected view node`; signals are now created with `signal(cx, ...)` in the component body. Both routers still called `.discover_shards().discover_procedures()`, which `Router::discover()` now does for you once `.runtime()` is mounted. The runtime endpoints moved to `/_topcoat/runtime/shards/<id>`, and a shard request now needs an `x-topcoat-identity` header and an `{"args":[...],"signals":{}}` envelope rather than a positional JSON array, so the htmx and server-runtime tests had to be rewritten.
- Lab 09's `the_shard_and_the_htmx_route_render_the_same_fragment` needed a real change rather than a rename. The shard's tracked read of its `Signal<String>` argument emits a `<!--::topcoat::dep("...")-->` marker that the htmx route has no reason to emit, so byte equality now holds only after the runtime's own `::topcoat::` comments are stripped. The markup either side of the marker is still identical.
- Labs 10-12 carried the same 0.7-era signal declarations, shard value argument, explicit shard/procedure discovery, and old runtime test wire format forward. They now use `signal(cx, ...)`, pass the page-owned search signal to `Signal<String>` shards as `$(query)`, rely on `.runtime().discover()`, give morphed vessel and work-order rows stable identities, and test `/_topcoat/runtime/...` with the shard identity header and signal envelope.
- Topcoat 0.8.0 treats an empty form or query value as `None` only for `Option<T>`. Lab 10's required create-work-order fields remain `String`, so empty values still reach its explicit validation; the persistence test now covers an empty title and berth as well as preserved invalid values.
- Labs 11-12 initially pulled both `topcoat-asset` 0.7.0 and 0.8.0 because the workspace's direct bundler dependency had not moved with `topcoat`. That produced incompatible `Asset` types in `fontsource_font!`; aligning the direct pin to 0.8.0 fixed it. In 0.8.0 `.discover()` also discovers fonts, so the explicit `.font(assets::GEIST)` registration was removed to avoid a duplicate font route.
- Lab 13 compiles and tests unchanged on 0.8.0. The release adds `TowerRoute::any(path, service)` as shorthand for `TowerRoute::new(Methods::Any, path, service)` when mounting a catch-all Tower subtree. The root `slipway/` capstone now carries the migrated Lab 12 runtime, discovery, stable-ID, and test-wire behavior while retaining its Lab 13 Tower route and layers.
